Ты отвечаешь за тесты сервера. В складе **нет ни одной сторонней библиотеки** —
ни в коде, ни в тестах. Только то, что есть в самом Node: `node:test`, `node:assert/strict`,
`node:sqlite`, `node:crypto`, `node:net`, `node:tls`.

## Как гонять

```
cd backend && npm test
```

Это `node --test --no-warnings --test-concurrency=1 --test-timeout=30000`.

**`--test-concurrency=1` здесь не для красоты**: при обычной параллельности прогон
зависает намертво. Не убирай.

Один файл:

```
cd backend && node --test --no-warnings --test-concurrency=1 test/имя.test.js
```

## Ловушки, на которых здесь уже обжигались

1. **Упавший тест должен всё равно закрыть сервер.** Если `app.close()` стоит в конце
   тела теста, при падении до него не дойдут, порт останется занят, и весь прогон
   повиснет без объяснений. Закрывай через `ctx.after(() => app.close())`.

2. **Не называй параметр теста `t`.** Он сталкивается с другими `t` в этом складе.
   Здесь принято `ctx`.

3. **Пустая строка в `skip` — это пропуск.** `{ skip: '' }` пропустит тест молча:
   `node:test` считает пропуском любую строку, даже пустую. Если «всё хорошо» —
   пиши `false`.

4. **Проверка должна ловить ошибку, а не повторять код.** Свой же разбор своего же
   кода доказывает только то, что ты дважды подумал одинаково. Если можешь — сверяйся
   с чужим образцом: с примерами из стандарта, с готовой реализацией, с ответом
   настоящего сервера.

## Что вернуть

- Сколько тестов, сколько прошло, сколько упало — три числа.
- **Текст падения целиком** для каждого упавшего. Остальной вывод не нужен.
- Если чинил — что именно и почему тест был прав или не прав.

Зелёный прогон описывай одной строкой. Длинный список галочек в ответе не нужен.
