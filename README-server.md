# Sklad Go — полноценная версия: backend + frontend

Две папки:

- `backend/` — сервер: регистрация и вход, подтверждение почты кодом из 6 символов, роли (владелец / сотрудник),
  подтверждение сотрудников владельцем, база SQLite, обновления в реальном времени. **Без внешних библиотек**
  (только встроенные модули Node.js), ничего устанавливать через npm не нужно.
- `frontend/` — сайт на HTML/CSS/JS: экраны входа и регистрации + сама программа (склад, долги, история, статистика, команда).

## Быстрый запуск (на своём компьютере)
Нужен Node.js версии **22.13 или новее** (nodejs.org).

```
cd backend
node server.js
```
Откройте http://localhost:3000. Сервер сам отдаёт сайт из папки `frontend`.

1. Нажмите «Создать аккаунт». **Первый зарегистрированный становится владельцем 👑.**
2. Код подтверждения почты в режиме разработки печатается **в окне, где запущен сервер** (строка `[mail] …`).
3. Остальные сотрудники регистрируются так же и ждут вашего «✓ Разрешить» во вкладке «Команда».

Проверка работоспособности: `cd backend && npm test` (автоматические проверки: права, коды, блокировки, реальное время, слияние изменений, словарь перевода).

## Чтобы письма уходили по-настоящему
Скопируйте `backend/.env.example` в `backend/.env` и укажите почтовый сервис.
Подойдёт Resend (resend.com): `MAIL_MODE=webhook`, `MAIL_WEBHOOK_URL=https://api.resend.com/emails`,
`MAIL_API_KEY=ваш ключ`, `MAIL_FROM=Sklad Go <no-reply@ваш-домен>` (домен нужно подтвердить в сервисе).
Для другого провайдера поправьте один блок в `backend/src/mailer.js`.

## Выкладка в интернет
1. Арендуйте небольшой сервер (VPS) или хостинг с Node.js ≥ 22.13.
2. Загрузите обе папки, запустите `node server.js` (лучше через `pm2` или `systemd`, чтобы перезапускался сам).
3. **Обязательно HTTPS** (например, Caddy или nginx + Let's Encrypt перед сервером): без него пароли идут открытым текстом.
4. Делайте **резервные копии файла базы** (`backend/data/skladgo.db` и файлы `-wal`, `-shm` рядом) — это все ваши данные.
5. В продакшене `DEV_MAILBOX` должен быть `false` (по умолчанию так и есть).
6. Если сайт и сервер на разных адресах: в `frontend/config.js` укажите адрес сервера, а в `.env` — `CORS_ORIGIN`.

## Долги: меню «⋯» на экране человека
Откройте человека во вкладке «Долги» и нажмите «⋯» рядом с именем:
- **Поиск по долгу** — фильтр по записям (слово из заметки, сумма, дата, сотрудник).
- **Переименовать долг** — меняет имя (двух людей с одним именем быть не может).
- **Добавить / изменить дату возврата** — общая дата для всего долга; после неё долг помечается «просрочено».
- **Настроить проценты** — простой процент на остаток долга между операциями, в месяц или в год, без начисления процентов на проценты. Показывается справочно («Проценты … · итого с процентами …») и попадает в выписку; сам баланс и записи он не меняет.
- **Напоминание** — дата, в которую программа на вкладке «Долги» покажет баннер «Напомнить сегодня». Кнопка «В календарь телефона» скачивает файл .ics: событие на этот день с будильником на 9:00.
- **Экспортировать в PDF** — откроется печать с готовой выпиской (имя, записи, итог, проценты); выберите «Сохранить как PDF» (на iPhone: «Поделиться» → «Сохранить в Файлы»).
- **Отправить в архив**, **Удалить долг** (с подтверждением вторым нажатием; удалённое можно восстановить во вкладке «История»).

## Сканер штрихкодов
- Кнопка сканера стоит справа от строки поиска на складе. Умеет EAN-13, EAN-8, UPC-A, Code 128, Code 39. Если в телефоне есть встроенный сканер (Android Chrome), используется он, иначе собственное распознавание (`frontend/barcode.js`) — работает без интернета и на iPhone. Картинки никуда не отправляются.
- Три режима: **Найти** (по умолчанию: навёл камеру, открылась карточка товара), **＋ Приход** и **− Расход** (каждый скан = ±1, камера остаётся включённой; режим нужно выбирать каждый раз, чтобы случайно не списать товар). Есть фонарик, ручной ввод номера и распознавание по фото («Из фото»).
- Штрихкод привязывается к товару: кнопка «Штрихкод» в карточке или поле в форме товара (рядом кнопка камеры). У каждого цвета/размера свой штрихкод. Один штрихкод нельзя привязать к двум товарам; 12-значный UPC-A приравнивается к EAN-13 с нулём.
- Неизвестный код: «Создать товар с этим штрихкодом» или «Привязать к существующему товару».
- Сканеры-«клавиатуры» (USB/Bluetooth) тоже работают: введите код в строку поиска и нажмите Enter. Поиск находит товар и по части штрихкода. Штрихкод есть в выгрузке остатков и в резервной копии.
- Камера в браузере работает только по **HTTPS** (на localhost тоже). Без неё остаются ручной ввод и «Из фото».
- Проверено: 132 тестовых изображения (чёткие, размытые, зашумлённые, наклонные, перевёрнутые, вертикальные) и 1500 картинок-помех без ложных срабатываний; в браузере с «камерой», показывающей штрихкод (22 проверки).

## Языки и валюта
- Интерфейс на **русском** и **таджикском** (Тоҷикӣ). Переключатель: на экране входа (вверху справа) и во вкладке «Команда / Кормандон». Язык по умолчанию выбирается по языку телефона.
- Переводится только то, что показывается на экране. Название товаров, имена, цвета и записи в данных остаются так, как их ввели; склад и долги от смены языка не меняются.
- Переводы лежат в **`frontend/tg.js`**: слева русская фраза, справа перевод. Их можно править обычным текстовым редактором. Перевод сделан без носителя языка, поэтому его стоит вычитать (термины: Ворид = приход, Хориҷ = расход, Қарз = долг, Анбор = склад).
- Если в `tg.js` нет перевода фразы, на экране остаётся русский текст (ничего не ломается). Чтобы увидеть, каких фраз не хватает: откройте программу на таджикском и в консоли браузера выполните `Object.keys(SKLAD_MISSING)`.
- **Валюта магазина** (сомонӣ, сум, тенге, сом, рубль, доллар) выбирается владельцем во вкладке «Команда», одна для всего магазина. По умолчанию сомонӣ.
- Ограничения: записи ленты «кто что сделал» хранятся на языке автора, а переводится только их начало; названия цветов внутри составных подписей (например, «Куртка · Чёрный») остаются как сохранены; Excel-выгрузки сделаны на языке интерфейса.

## Работа без интернета
- Сайт и программа сохраняются на телефоне (service worker) и открываются без связи. Для этого на сервере нужен **HTTPS** (на localhost работает и так).
- Все изменения (приход, расход, новые товары, долги) сразу записываются на телефон и помечаются «не отправлено». В шапке написано «нет связи · данные на телефоне».
- Когда связь вернулась, программа сама отправляет изменения и **сливает** их с тем, что за это время сделали коллеги (`frontend/merge.js`, проверено автотестами).
- Если выйти из аккаунта, пока есть неотправленное, программа предупредит.

## Что реализовано
| Область | Как сделано |
|---|---|
| Пароли | scrypt с солью, не хранятся в открытом виде; минимум 8 символов, буквы и цифры |
| Почта | код из 6 символов, живёт 15 минут, 5 попыток, повторная отправка не чаще раза в минуту |
| Сессии | случайный токен 256 бит, в базе хранится только его хэш; выход и сброс пароля закрывают сессии |
| Защита от подбора | ограничения по почте и по IP, одинаковый ответ на неверный пароль и несуществующую почту |
| Роли | владелец видит телефоны и почты всех; сотрудник — только имена; блокировка мгновенно закрывает доступ |
| Лента изменений | автора и время ставит **сервер**, подделать нельзя; записи нельзя менять и удалять |
| Реальное время | сервер рассылает события (SSE) — изменения других сотрудников видны сразу |
| Данные | версии документов (заголовок `If-Match`) для защиты от перезаписи; лимит размера |
| Безопасность сайта | строгая политика CSP, `X-Frame-Options`, без `eval` |

## Ограничения (честно)
- **Бот-помощник отключён** (нужен ключ Claude API на сервере; ключ нельзя класть в сайт).
- **SMS-коды на телефон не реализованы**: подтверждение через почту. SMS требует платного шлюза.
- Одновременные правки сливаются автоматически (остатки складываются как разница, новые товары и долги сохраняются с обеих сторон). Если двое одновременно поменяют одно и то же поле одного товара (например, название), побеждает тот, кто отправил позже.
- Резервные копии и выкладка на сервер: см. `deploy/DEPLOY.md`.
- Данные из версии внутри Claude сами не переносятся: сделайте «💾 Резервная копия» там и «📥 Восстановить из копии» здесь.
- Первый вход на новом устройстве требует интернет. Дальше программа открывается и работает без него. Заблокированный сотрудник, у которого нет связи, до первого подключения видит данные, уже сохранённые на его телефоне. Записи ленты «кто что сделал» без интернета не копятся.
- Проверено автоматическими тестами и в тестовом браузере на одной машине; нагрузочных испытаний и проверки на реальном
  сервере с HTTPS и почтой не было.
- Для магазинов приложений (Google Play / App Store) сайт можно упаковать через Capacitor: `webDir` указывает на `frontend`,
  сервер нужно выложить в интернет (адрес в `frontend/config.js`).
