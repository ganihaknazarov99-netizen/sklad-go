# Sklad Go

Простой учёт склада и долгов для маленького магазина — работает прямо в браузере, на телефоне и компьютере.

**Открыть демо:** https://ganihaknazarov99-netizen.github.io/sklad-go/

## Две версии в этом репозитории

| Где | Что это | Чем запускается |
|---|---|---|
| корень (`index.html`, `app.js`, …) | лёгкая версия: работает прямо в браузере, сервер — Supabase. Её и показывает демо по ссылке выше | GitHub Pages, сервер не нужен |
| `frontend/` + `backend/` + `deploy/` | полная версия: свой сервер на Node, вход по почте с паролем, штрихкоды, таджикский язык, Telegram | `node backend/server.js`, см. [README-server.md](README-server.md) |

Это разные программы, а не части одной. Пока они живут рядом; когда станет ясно,
какая остаётся главной, вторую можно будет убрать.

## Что умеет

- Остатки товаров с размерами и цветами, приход и продажа в одно касание
- История операций по дням
- Долги: кто кому должен, частичные возвраты, сроки
- Команда: владелец и сотрудники, лента изменений
- Светлая и тёмная тема

## Два режима

Программа сама выбирает режим по файлу `config.js`:

- **Демо** (поля в `config.js` пустые) — данные только в этом браузере, вход не нужен.
  Кнопка «Сбросить» вверху возвращает демо-данные магазина.
- **Рабочий** (поля заполнены) — вход через Google, общий склад на всех устройствах,
  подтверждение сотрудников владельцем и лента изменений.

## Подключение сервера

Сервер — проект Supabase (бесплатного тарифа хватает небольшому магазину).

1. Заведите проект на [supabase.com](https://supabase.com).
2. **SQL Editor → New query** → вставьте целиком `supabase/schema.sql` → **Run**.
   Это создаёт таблицы, права доступа и проверку версий.
3. **Authentication → Providers → Google** → включите и вставьте Client ID и Client Secret
   из [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
   В Google Cloud в «Authorized redirect URIs» добавьте адрес, который показывает Supabase:
   `https://<ваш-проект>.supabase.co/auth/v1/callback`.
4. **Authentication → URL Configuration**:
   - **Site URL**: `https://skladgo.vercel.app`
   - **Redirect URLs** — все адреса, по которым программа открыта, иначе вход
     с них не вернётся обратно:
     ```
     https://skladgo.vercel.app
     https://sklad-go-gani26.vercel.app
     https://ganihaknazarov99-netizen.github.io/sklad-go/
     ```
5. **Project Settings → API** → скопируйте Project URL и ключ `anon public` в `config.js`.
   Этот ключ открытый: что можно делать с данными, решают правила из `schema.sql`.
6. Закоммитьте и запушьте — через минуту сайт заработает с сервером.

**Первый, кто войдёт, становится владельцем.** Остальные после входа ждут, пока владелец
нажмёт «Разрешить» на вкладке «Команда». Демо-данные с этого устройства стираются при
первом настоящем входе, чтобы не уехать на сервер.

## Что ещё не подключено

Вкладка «Помощник» (бот) в рабочем режиме отвечает «недоступен»: для неё нужен
серверный ключ Claude API, его нельзя держать в коде страницы.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Страница и стили |
| `app.js` | Логика приложения |
| `backend.js` | Связь с сервером: вход, склад, команда, лента |
| `config.js` | Адрес и ключ вашего проекта Supabase |
| `supabase/schema.sql` | Таблицы и права доступа — выполняется в Supabase |
| `merge.js` | Слияние изменений телефона и сервера |
| `demo.js` | Демо-данные и демо-команда |
| `logo.svg` | Логотип |
| `frontend/` | Полная версия: страницы, стили, сканер штрихкода, переводы |
| `backend/` | Её сервер на Node: вход, роли, база SQLite, события |
| `deploy/` | Caddy и systemd для развёртывания полной версии |
| `README-server.md` | Описание полной версии |

## Как обновить сайт

1. Замените файлы в этой папке.
2. В GitHub Desktop: **Commit to main** → **Push origin**.
3. Через минуту сайт обновится.
